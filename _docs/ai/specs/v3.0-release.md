# Spec: Signal Sentinel Scanner v3.0.0

Status: awaiting approval
Author: Droid (orchestrator, implementing directly per user instruction 2026-09-19)
Branch model: `release/v3.0` <- feature branches via PR; `release/v3.0` -> `main` at the end

## 1. Goal

Ship v3.0.0 as a single major release that bundles:

- the seven findings from the 2026-09 project review,
- the fourteen additions from the external competitor/threat research,
- Theme 1 of `ROADMAP_V3.0.md` (context-aware segmentation, versioned scoring rubric, keyword pruning).

Theme 1 changes grades on unchanged input, which is the SemVer MAJOR trigger already
argued in the roadmap. Everything else is additive but rides the same version.

## 2. Corrections to the research report (found while mapping the code)

| Research claim | Reality | Effect on plan |
|---|---|---|
| `McpConnection` only calls `tools/list` | `ToolEnumerator` already calls `resources/list` and `prompts/list` and stores them on `ServerEnumeration`; no rule reads them | WP2 is rules + capturing `instructions`, not transport |
| "sampling/elicitation capabilities" are declared by servers | They are client capabilities; servers exercise them by sending `sampling/createMessage` / `elicitation/create` to the client | SS-033 detects unsolicited server-to-client requests during enumeration instead |
| `--policy` should wire to `policies/*.yaml` | Those files are Gateway runtime policies (cost ceiling, circuit breaker) | `--policy` gets its own small JSON preset format (WP7) |

### WP2 `feat/mcp-surface`
- `McpInitializeResult.Instructions` captured; `ServerEnumeration.ServerInstructions`.
- `McpServerCapabilities` gains `Experimental` (JsonElement?) and `Completions`.
- `McpConnection` records any inbound server-initiated message (has `method`) received
  while awaiting responses into `ServerEnumeration.UnsolicitedRequests` (method + first
  200 chars of params, sanitised). For requests (has `id`) on stdio/WebSocket it responds
  with JSON-RPC error -32601 so the session stays well-formed; over Streamable HTTP every
  SSE frame is inspected and server-initiated frames are recorded, not declined.
- `McpConnection` also records JSON-RPC `error` objects (method, code, sanitised message)
  into `ServerEnumeration.ProtocolErrors`. This is the capture side of SS-040 (WP9);
  WP9 only needs to add the rule.
- SS-030: `InjectionPatterns` over prompt `description` and each argument `description`.
- SS-031: `InjectionPatterns` over resource `name`/`description`; plus URI heuristics
  (`file://` to home/credential paths, `data:` URIs, non-standard schemes).
- SS-032: `InjectionPatterns` over `instructions`, plus a cross-server-directive regex
  (steering the agent away from other servers' tools or past user confirmation, High) and
  a >4 KB length check (Low). AST04 + AST05 (the shadowing branch is an agent-goal
  manipulation concern).
- SS-033: fires once per distinct unsolicited method; Critical for `sampling/*`, High for
  `elicitation/*` and `roots/*`, Medium for other requests, Low for unknown notifications.
  Standard `notifications/*` (progress, list_changed, message, cancelled) are ignored.
  Does not skip servers whose connection later failed.
- SS-INFO-005: one Info finding per server summarising `tools.listChanged`,
  `resources.subscribe`, `experimental` keys, `completions`, `logging`.
- `McpProtocolRules` set extended with SS-030..033, SS-INFO-005.

### WP3 `feat/skill-forensics`
- `IntegrityVerifier`: parse `SHA256SUMS` (`<hex>  <path>` lines), hash each referenced
  file, report per-file match/mismatch/missing. Recognise `skill.oms.sig` and `*.oms.sig`
  as signature files. `IntegrityReport` gains `ChecksumResults`.
- SS-034: fires High for any mismatch, Medium for files listed but missing.
- `ScriptInventory`: add `.rb .pl .php .lua .bat .cmd .zsh .vbs` (`ScriptLanguage` gains
  Ruby, Perl, Php, Lua, Batch, VbScript; `.zsh` maps to Bash).
- New `SkillParser/FileForensics.cs`: bounded recursive walk (500 files, 2,000
  directories, reads only the first 64 bytes of each file, symlink-safe, same exclusions
  as `ScriptInventory`) producing `FileArtefact` records: magic-byte type (PE with
  `e_lfanew` check, ELF, Mach-O, ZIP/JAR/wheel, gzip, bzip2, xz, 7z, RAR, Java class,
  CPython pyc with flags check, shebang), extension, size, hidden flag, executable flag.
- SS-035 fires on: magic/extension mismatch (High), executable binary anywhere (High),
  double extension like `.md.exe` (High), archive present (Medium), opaque `.bin`/`.dat`
  (Medium), executable-bit file with no type or extension (Medium), orphan `.pyc` with no
  sibling `.py` (Medium), compiled Java class (Medium), hidden files or files under
  non-allowlisted dot-directories (Low).
- Checksum verification is bounded: 1 MB manifest, 1,000 lines, 50 MB per file, 200 MB
  aggregate, entries deduplicated by resolved path, symlinked entries must resolve inside
  the package. SS-024 calls `Verify(skill, verifyChecksums: false)` so hashing runs once.
- Known limitation: directories excluded from the walk (`node_modules`, `__pycache__`,
  `dist`, `build`, `venv`) are not inspected by SS-035.
- `SkillDefinition.Artefacts` populated by `SkillReader`.

### WP4 `feat/confusables-overlap`
- `Core/Security/Confusables.cs`: curated TR39-style map for Latin lookalikes (Cyrillic,
  Greek, fullwidth, mathematical alphanumerics), invisible/format chars (ZW*, RLO, LRO,
  BOM, soft hyphen), mixed-script detection, skeleton function.
- SS-036: tool names, prompt names, resource names, server names, skill names.
  High when the skeleton collides with another identifier in the same scan (shadowing).
  Medium for invisible/control characters, disallowed script mixing, or a standalone
  fullwidth/mathematical/letterlike clone. Low (confidence 0.5) for a single-script
  non-Latin word whose letters all happen to have Latin lookalikes ("ресурс"), since
  that is what legitimate localised names look like too.
  Only the non-ASCII member(s) of a collision are reported; the ASCII identifier is the
  impersonated party. Collision identity uses an NFC + case-fold key, so "Ресурс" vs
  "ресурс" and NFC vs NFD "café" are one name, not a collision; ASCII-only collisions
  are left to SS-023. ASCII-ness is judged on the original string because NFKC folds
  fullwidth and mathematical letters to ASCII. Latin-only identifiers that fold to ASCII
  via diacritics or symbols (Turkish "sıralama", "acme™", "web²", "µservice") are not
  whole-script confusables. Script policy is UTS #39 Moderately Restrictive: the
  Highly Restrictive CJK combinations plus Latin with any one script that has no Latin
  lookalikes (Cyrillic, Greek, Cherokee and Armenian may never mix with Latin).
  Variation selectors after a symbol, ZWJ next to a symbol, and ZWJ/ZWNJ between two
  non-Latin letters are treated as orthographic, not invisible. Disconnected servers
  contribute only their server name. Skill findings set `ServerName` to the skill name
  (as every other skill rule does) so scope, suppression and `CanonicalSkillName`
  resolve. Mapped to MCP03 for MCP-sourced findings; skill and server findings carry no
  `ToolName`. Not in `McpProtocolRules` because the rule spans skills too.
  Known gaps: Turkish "İ" does not case-fold to "i" under invariant culture; the
  lookalike map is curated, not the full UTS #39 table.
- SS-037: pairwise Jaccard on normalised description token sets across skills; fire at
  >= 0.80 when names differ. Evidence lists both skills and the score. Tokens are
  lower-cased alphanumerics of length >= 3 minus a stop-word list that includes
  marketplace trigger boilerplate ("use this skill whenever the user asks ..."); descriptions
  with fewer than 5 tokens are skipped. Pairs with the same `CanonicalSkillName` or the
  same `FilePath` are skipped (duplicate installs are not hijacking). Bounded to the
  first 2,000 skills (~2M set comparisons, about 1.3 s). Confidence 0.9 at >= 0.95
  similarity, otherwise 0.75. The finding is attributed to the first skill
  (`ServerName`, `SkillFilePath`); both paths appear in the description. The tokeniser is
  whitespace/punctuation based, so unspaced CJK or Thai descriptions collapse to a few
  tokens and are effectively not compared.

### WP5 `feat/bash-taint`
- `Core/Security/PipelineTaint.cs`: line-oriented analysis for Bash/Zsh, PowerShell, Python,
  JavaScript, and fenced code blocks in instructions. Sources: `curl`, `wget`,
  `Invoke-WebRequest`, `iwr`, `Invoke-RestMethod`, `urllib.request.urlopen`, `requests.get`,
  `fetch(`, `http.get`. Sinks: `| sh`, `| bash`, `| zsh`, `| python`, `| node`, `eval`,
  `Invoke-Expression`, `iex`, `exec(`, `subprocess.*(shell=True)`, `os.system`,
  `child_process.exec`. Also `base64 -d | sh` and `echo <b64> | base64 -d | bash`.
- Direct pipe = Critical. Variable-mediated within 20 lines (assign from source, later
  used in sink) = High. Evidence is the sink line, truncated.
- SS-038 applies to `skill.Scripts` and to fenced code segments of `InstructionsBody`.

### WP6 `feat/osv-lookup`
- `--osv` opt-in flag; refused under `--offline`.
- `SkillParser/DependencyExtractor.cs`: `pip install a==1.2`, `npm install a@1.2`,
  `requirements.txt`, `package.json` (dependencies + devDependencies), `pyproject.toml`
  `[project] dependencies` (regex-level). Unversioned references are recorded but not queried.
- `Osv/OsvClient.cs`: POST `https://api.osv.dev/v1/querybatch`, max 100 packages,
  10 s timeout, no retries, User-Agent set. Response parsed for id, summary, severity
  (CVSS vector -> Critical/High/Medium/Low bands).
- SS-039 per vulnerable package. SS-INFO-006 lists packages found when `--osv` is absent,
  when offline, or when the query fails (so the operator knows what was not checked).

### WP7 `feat/policy-presets`
- `--policy <default|strict|defence|path.json>`.
- JSON: `{ "severityOverrides": {"SS-024":"High"}, "disabledRules": ["SS-INFO-005"],
  "failOn": "medium", "minConfidence": 0.5 }`. Presets are embedded resources.
- `strict`: supply-chain rules (SS-004, SS-021, SS-024, SS-029, SS-034, SS-039) one band up,
  `failOn: medium`. `defence`: every rule one band up, `failOn: low`, `--offline` implied.
- Applied after dedup, before confidence filter. Explicit CLI flags override the preset.
- `PolicyConfiguration` (already on `ScanContext`, currently unused) carries the overrides.

## 5. Acceptance criteria

- Release build: 0 warnings, 0 errors on Windows, Ubuntu, macOS CI matrix.
- Test count grows from 422 to >= 560 (roughly 10 per new rule plus property tests plus
  segmentation corpus).
- Every new rule has: constant in `RuleConstants`, entry in `RuleAstMapping`, entry in
  `OwaspMapping`/`OwaspMcpMapping` where applicable, registration in `RuleEngine`, help
  text line, `--list-rules` line, and a test class.
- `sentinel-scan --skills tests/Fixtures/segmentation --offline` runs clean.
- `--offline` still blocks every network path including `--osv` and `--agent-card <url>`.
- Version literal `3.0.0` appears exactly once in tracked source (`Directory.Build.props`);
  every other occurrence is derived or lives in CHANGELOG/MIGRATION prose.
