## Two judgement calls (please confirm in VERIFY)

1. **F11 sink definition narrowed to *dynamic* process execution.** Spec F11 says "the same
   script ... also matches ... `ProcessExecution()`", but office-helper's `convert.py`
   contains both `[::-1]` and `subprocess.run(["soffice", ...])`, and F14 requires **zero**
   SS-015 on the corpus. Taken literally the two requirements contradict. Resolved by reusing
   F13's grading: a fixed literal command cannot execute a decoded/reversed string, so it is
   not a sink; `os.system(cmd)` and friends still are. This keeps
   `F11_Ss015_StillFiresMedium_OnStringReversalIntoProcessExecution` green and the corpus
   clean. Implemented as `SkillScriptPayloadRule.HasDynamicProcessExecution` (internal).
2. **F5 keeps the upper-case `API_KEY` / `SECRET_KEY` spelling firing** (case-sensitive
   `(?-i:\bAPI_KEY\b)`). Without it the pre-existing
   `ToolPoisoningRuleTests.Evaluate_WithSensitiveFileAccess_ReturnsCriticalFinding("Gets
   API_KEY from environment variables")` regresses. It is an environment-variable reference,
   which F5 explicitly retains; the spec's prose examples (`api_key`, `API-key`, `secret_key`)
   are unaffected, and `ANTHROPIC_API_KEY` does not match (no word boundary after `_`).

Also of note: F7's object list keeps `safety|guidelines?|rules?|restrictions?|prompts?` so
`"You MUST override the safety guidelines"` (pinned by `ToolPoisoningRuleTests` and
`SkillPatternAccuracyTests`) still fires. This is the narrowest addition to the spec's list
that keeps both suites green.

## Notes / Follow-Up

- Nothing new was introduced with a `){n,m}?` shape; the hygiene guard covers every
  `GeneratedRegex` accessor in `Core.Security` and `Scanner.Rules`, including private ones.
- Backslash escaping a backtick does **not** protect a markdown code span (backslash escapes
  are inert inside code spans), so `&#96;` was chosen over the `\`` form the test also
  accepts. Same for the raw newline: it is replaced by a space rather than `\n` text.
- Mid-round the Release build failed twice with MSB3021/MSB3027 - two PowerShell host
  processes held handles on `src/SignalSentinel.Scanner/bin/Release/net10.0/*.dll`. Resolved
  by renaming the locked outputs aside; the stale `.locked` files were deleted afterwards and
  `bin/` is gitignored. Worth knowing if CI ever runs builds and scans from the same shell.
- Upstream bug report to dotnet/runtime for the `(?:X){n,m}?` miscompilation remains a
  follow-up for the owner, as does the lessons-loop entry (AGENTS.md "Lessons Loop": this is a
  pattern-shaped defect that affected four constructs, one of them shipped).
