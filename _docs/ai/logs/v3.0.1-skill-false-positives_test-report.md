## Ambiguities resolved (please confirm during IMPLEMENT/VERIFY)

1. **F13 list arguments.** Strictly, `subprocess.run(["soffice", ..., path])` contains a bare
   identifier and would be High, yet F13/F14 require exactly that corpus line to be Medium.
   Resolved: for a list/array first argument the **first element** decides the shape. Tests
   pin `[literal, ...]` -> Medium and `[identifier, ...]` -> High.
2. **F14 "zero SS-011" needs one un-itemised fix.** claude-api's description contains the
   55-character run `generate/summarize/extract/classify/rewrite/converse`; `/` is in the
   base64 alphabet, so INJECTION-006 `Base64Payload()` grades it Medium. That is not covered
   by F5-F9 but blocks the specced zero. Pinned by
   `F14_Ss011_DoesNotFire_OnSlashSeparatedProseWordLists` with the counterpart
   `F14_Ss011_StillFires_OnRealBase64Blob` (a real 140-char base64 blob with digits).
3. **Corpus rule set.** `RealWorldSkillCorpusTests` runs exactly the five rules this spec
   touches (SS-011/014/015/016/018), not the whole skill registry, so "zero Critical" means
   zero Critical from those rules. The corpus does also raise 7x SS-012 Medium and 7x SS-024
   Medium, both explicitly out of scope.
4. **F1 chomping and trailing newlines.** Tests assert the YAML 1.2 semantics named in the
   spec: `>`/`|` keep one trailing `\n`, `-` strips it, `+` keeps all (asserted as
   "ends with `\n\n`" rather than an exact count).
5. **F8 location.** The mention-vs-use gate is tested through `InjectionPatterns.JailbreakAttempt()`
   *and* through `SkillInjectionRule`, because spec section 3 lists only `InjectionPatterns.cs`
   as changing. If the implementation ends up in the rule instead, the regex-level test must be
   revisited with the Delegator rather than silently relaxed.
6. **No `verify-results.json` exists** in this repo, so no `redBaseline` field was set; the
   raw red output is filed under `_docs/ai/verify/evidence/`.

   post-newline content to survive on the same line (escape, do not truncate).
