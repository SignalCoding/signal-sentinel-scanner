## Deviations From Literal Spec Text (all documented in-code at `SkillScopeViolationRule.cs:122-153`)

Forced by `RealWorldSkillCorpusTests.N3_Corpus_ProducesNoSkillScopeViolationFindings`
(zero SS-012 across the real fixture corpus), verified against every `.md` file in
`Fixtures/RealWorldSkills` and against every currently-shipped test:

1. **Filesystem verbs narrowed**: dropped `read`, `create`, `copy` (kept `write|delete|remove|overwrite|modify|edit|save|move|list`). skill-creator's unmodified SKILL.md genuinely contains "create directories" (real action), "read file X" (a quoted example in prose about triggering), "write a standalone HTML file", "copy to the output directory" - structurally identical to the required genuine-fire test and unfixable by gap width alone. No shipped test requires these verbs to fire for filesystem.
2. **Filesystem target narrowed**: dropped bare singular `file` (kept plural `files`, plus `directory`/`directories`/`folder(s)`) - same skill-creator conflict; the one required genuine test uses plural "files".
3. **Shell target narrowed**: dropped `scripts?` (kept `commands?|shell|subprocess|terminal|process`) - skill-creator's "run a script" / "run the aggregation script" is genuine prose, not a noun mention, but has no purpose declaration route; no shipped test needs "script" as target.
4. **`curl`/`wget` matched case-sensitively** (`(?-i:curl\s|wget\s)`) instead of the literal spec's case-insensitive `curl\s`/`wget\s`: the real claude-api fixture and the office-helper fixture (crafted from the spec's own FP table) both contain "a shell/cURL project" verbatim; a case-insensitive `curl\s` fires on that mixed-case noun mention. Case-sensitive lowercase still fires on the genuine test ("curl -X POST ...") and the pre-existing `EveryEmittedFinding_CarriesAstCodes` test ("Issues curl and wget requests externally.").

All four were checked against the full fixture corpus (`grep -rinoP` per shape) before and after; no other skill (academy-guide, algorithmic-art, claude-api, coauthor, mcp-builder) is affected - claude-api and mcp-builder already declare network via "api" in their descriptions, and claude-api additionally declares filesystem via "target file" in its TRIGGER text.

## Risks and Notes

- The filesystem/shell verb and target narrowing (deviation 1-3 above) means SS-012 will no longer catch "read the file", "create a file", "copy the file" or "run a script" as filesystem/shell scope violations, even when genuinely undeclared. This trades detection breadth for corpus-verified false-positive elimination, per the N3 acceptance gate. No CHANGELOG entry beyond the general SS-012 reshaping note, since these are sub-deviations of the same N1 migration, not separate rule changes.
- `curl`/`wget` case-sensitivity is a narrow, verified-safe heuristic (corpus-checked); a skill that writes `CURL` or `WGET` in all caps as a genuine invocation (unusual) would not be caught by the concrete-client path, though the verb-shape network patterns and other concrete clients remain unaffected.
