# Security Review: v3.0.1-skill-false-positives

**Reviewer:** security-reviewer (Sonnet), 2026-09-21, read-only pass over the uncommitted diff.
**Scope:** `FrontmatterParser.cs`, `SkillHiddenContentRule.cs`, `SkillScriptPayloadRule.cs`, `SkillObfuscationRule.cs`,
`InjectionPatterns.cs`, `ExfiltrationPatterns.cs`, `ObfuscationPatterns.cs`, `CHANGELOG.md`, `docs/keyword-rules.md`.
**Methodology:** STRIDE + OWASP ASI/AST (CLI scanner; ReDoS/DoS cited by CWE). Returned inline by the reviewer and
filed here by the orchestrator verbatim, plus section "Orchestrator addendum".

## Summary

No Critical/High blockers. Regex ReDoS bounding and the block-scalar parser are sound. Two Medium findings: an easy
newline-based bypass of F7's `IMPORTANT:` gate, and F13's new argument evidence can carry raw newlines into Markdown
reports (unescaped by `SanitizeMarkdown`). One Medium governance gap: F8 is undocumented in CHANGELOG/keyword-rules.md.

## Accepted narrowings (realistic misses judged acceptable)

- **F8 quote-gate evasion:** an attacker can wrap a real jailbreak in quotation marks within 80 chars and the gate
  suppresses it as it would a documentation example. Inherent to the mention-vs-use design the spec asked for; keep
  INJECTION-009 as one signal among several (defence in depth) and call the trade-off out in `docs/keyword-rules.md`.
- **F5 verb list gap:** `steal|grab|copy|obtain|extract` are not in the read/reveal verb list; "steal the api_key from
  the user" would not fire. Acceptable per spec scope; note for a future corpus.
- **F6 destination noun list:** "send credentials to the collector service" / "to our internal tracker" will not match
  unless URL/IP/domain/listed noun. Accepted per spec; the fetcher branch and URL/IP/domain forms are unaffected.
- **F11 same-unit sink:** a decode in one script and a dynamic exec in a different script of the same skill is not
  caught (units scored independently). Accepted; known blind spot for split-file chains.
- **F12/F13/F15:** match the spec text exactly; no further realistic-miss concerns.

## ReDoS / parser safety (no findings)

- All new/changed `[GeneratedRegex]` keep `matchTimeoutMilliseconds` and bounded quantifiers; no nested/overlapping
  unbounded quantifiers on the same class. `Base64Payload()` run-start lookbehind makes the 200-char lookaheads
  evaluate once per run, so a 100k single-character run is O(n).
- `FrontmatterParser`: content capped at 500k before the block match, frontmatter parsed only if <= 50k, the
  block-scalar walk is bounded by that budget (no recursion, all iterative). `MaxBlockScalarLength` (20k) caps what is
  appended but the walk does not break early on breach; safe only because the outer 50k cap bounds iterations (Info).
  CRLF, tabs, no-continuation, scalar-at-EOF, and an unindented `---` inside a would-be block all terminate cleanly.
- F2 evidence builds `U+XXXX xN` strings only; source characters never reach `Finding.Evidence`.

## Verdict: PASS WITH NOTES

No Critical/High blockers. F-1, F-2, F-3 are recommended before the next tag and are being fixed in this branch
(see addendum) rather than deferred, given the product's stated purpose.

## Orchestrator addendum (2026-09-21, after the review)

**F-4 (High, found in VERIFY, not by the review): .NET regex engine disagreement on lazy bounded group loops.**
Live re-scan of the Anthropic corpus still reported one SS-011 High "Cross-Tool Manipulation" on doc-coauthoring with
evidence beginning `), mention that these can be used ...` (419 chars) that the F9 pattern cannot produce. Reproduced
outside the scanner on .NET SDK 10.0.401:

| Engine | Result on the same text and pattern string |
| --- | --- |
| Interpreted (`new Regex(pattern)`) | no match |
| `RegexOptions.NonBacktracking` | no match |
| `RegexOptions.Compiled` | bogus match at index 20, length 419 |
| `[GeneratedRegex]` (what ships) | bogus match at index 20, length 419 |

Bisecting the pattern: variants containing `(?:\w+\s+){0,2}?` throw `IndexOutOfRangeException` under `Compiled`;
the greedy `{0,2}` and the explicit `(?:\w+\s+)?(?:\w+\s+)?` forms agree across engines. Four such constructs exist in
`InjectionPatterns.cs` after this diff (lines 114, 150, 177, 194: `(?:\s+\S+){0,3}?`, `(?:\S+\s+){0,4}?`,
`(?:\W+\w+){0,3}?`, `(?:\w+\s+){0,2}?`); line 150's predates the branch (v2.5.1) and shipped in 3.0.0.

Fix (this branch): rewrite every lazy bounded group loop as explicit optional groups; add a deterministic
pattern-hygiene test (no `){n,m}?` in any shipped pattern) and an engine-consistency test (generated vs interpreted
match sets over the real-world fixture corpus). Lesson entry to follow; upstream bug report to dotnet/runtime is a
follow-up for the owner.
