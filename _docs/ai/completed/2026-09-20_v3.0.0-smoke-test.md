## 2. Defects

| Id | Severity for release | Where | What | Proposed fix |
| --- | --- | --- | --- | --- |
| D1 | High | `McpClient/McpConnection.cs` ~565 `InitializeAsync` | Hard-codes `protocolVersion: "2024-11-05"`. Servers echo it back, so SS-INFO-004 "negotiated legacy version" fires on **every** server (Learn and DeepWiki support 2025-06-18). `AuthProbeService.cs:40` already sends 2025-06-18. | Request `McpProtocolVersions.Current` (fall back on the server's offered version per spec), record the server ceiling, and only fire SS-INFO-004 when the *server's* version is legacy. |
| D2 | High | `Program.cs` ~906–929 | `--remote http(s)://` always sets `McpTransportType.Http` (documented as legacy HTTP+SSE) although the client speaks Streamable HTTP (POST + SSE unwrap, `McpConnection.cs` ~280). SS-INFO-004 "uses the legacy HTTP+SSE transport" fires on every remote. | Assign `StreamableHttp` for `--remote`. Rules at `OAuthComplianceRule.cs:43`, `NonPublicTargetRule.cs:47`, `MissingAuthRule.cs:30`, `MissingAuthProbeRule.cs:49`, `AuthProbeService.cs:59` already accept both. |
| D3 | High | `McpConnection.cs` 643–647 `SendNotificationAsync` | HTTP branch posts with `_httpClient.PostAsync` directly, bypassing the request builder that adds `Mcp-Session-Id` (884–894). `notifications/initialized` arrives sessionless; stateful servers (SpaceMolt) then reject `tools/list` with "Session not initialized". Verified with curl that the session header fixes it. | Route notifications through the same request builder. |
| D4 | High | grading / `SeverityScorer` + report | Failed connection (`serversConnected: 0`) and 401-gated servers with zero tools inspected still grade **A**, exit 0. | Grade `Inconclusive` (or cap at "not assessed") when no server connected / no surface enumerated; make it obvious in every format. |
| D5 | Medium (FP) | `Core/Security/InjectionPatterns.cs:103` INJECTION-001 | `\b(?:ALWAYS|NEVER|MUST)\s+(?:…return…)` matches the defensive sentence "Read-only and never returns credential values" (HF `hf_whoami`) → SS-001 High. | Exclude negated/defensive phrasing (`never returns`, `never return(s) … values`), or require an object that is an exfil target. Add regression test. |
| D6 | Medium (FP) | SS-008 rule (`SensitiveDataAccess`/credential heuristics) | "Credential Access" **Critical** on `hf_whoami` and on Chainflip swap/quote tools (no credential handling in descriptions); "PII Access" High on `microsoft_docs_search`. Drives Chainflip to F/0 and HF to D. | Review the keyword sets: "token" in a crypto-swap context, "user" in "whoami", and whatever matched on `microsoft_docs_search`. Consider dropping Critical to High unless a credential *source* and *sink* both appear. |
| D7 | High | `McpConnection.cs` HTTP path | No support for legacy HTTP+SSE (`GET /sse` → `endpoint` event → POST `/messages/?session_id=`). POST to `/sse` → 405 → SS-INFO-001 "Non-MCP endpoint" → A/100. Every DVMCP server passes when scanned via its documented endpoint. Contradicts the `McpTransportType.Http` docstring and SS-INFO-004 wording. | Either implement the legacy SSE handshake (open GET stream, read `endpoint`, post there, correlate by id) or, at minimum, detect `text/event-stream` on GET / 405 on POST and report "legacy SSE endpoint, not scanned" as a Medium finding instead of Info + A. |
| D8 | Medium | SS-020 `AuthProbeService` | RFC 9728 metadata quality not distinguished: Linear (resolves), Sentry (`resource_metadata` 404s), Atlassian and GitHub Copilot (no `resource_metadata`) all get the same Info. GitHub Copilot 401 `text/plain` with `WWW-Authenticate` is misclassified as Non-MCP. | Treat any 401 carrying `WWW-Authenticate: Bearer` as an MCP auth challenge; add Low/Medium variants for missing or unreachable `resource_metadata`. |
| D9 | Low (cosmetic) | SS-042 rule | Info text leaks the exception type (`JsonReaderException`). | Map to "response was not JSON". |
| D10 | Medium (gap) | `ResourcePoisoningRule` / SS-008 | Resources advertising credentials by name, URI or description (`internal://credentials`, "Internal system credentials - DO NOT SHARE", "RESTRICTED ACCESS") produce no finding. `SensitiveFileUri` only matches file paths; INJECTION-003 lacks plain `credential(s)`/`password`; SS-008 markers only scan tools. | Apply the SS-008 sensitive-data markers to resource name/URI/description; add `credentials?`/`secrets?` URI path segments to the resource URI check. |
| D11 | Low | stdio transport | A stdio server that exits immediately (import error) is reported as "Timeout waiting for response" instead of "process exited (code N)". Related to the "stdio EOF hot loop" backlog item. | Surface process exit + stderr tail. |
| D12 | Medium | `Program.cs` argument handling | `--remote` private-address refusal prints the error and then the help text, **exit 0**. Same root cause as the "parse errors exit 0" backlog item. | Return exit 2 on every argument/policy rejection. |

Rubric observation (not a defect, recorded for the rubric owner): 12 High findings at score 0 still grade **C** because only Critical findings move a report to D/F.

## 3. Genuine detections confirmed

SS-026 on Learn `microsoft_docs_search`; SS-041 ×12 on DVMCP source; SS-001 tool poisoning on challenge 2; SS-031 on challenge 6 `get_api_keys`; SS-005 on challenge 8; SS-002 "Dangerous Operation" on challenge 8 executors; SS-010 cross-server exfiltration paths (file read → network send) across challenges 2/3/9/10; SS-042 "Declares No Authentication" on agentcard.net. All `--offline` guard rails behave as documented.

## 4. Recommendation (original)

Do **not** tag `v3.0.0` from `b0d7327` as-is. D1, D2 and D7 make SS-INFO-004 and the legacy-transport story visibly wrong on the very first scan any user runs, and D3/D4 mean a stateful Streamable HTTP server can fail to connect and still be reported A/97. Fix D1–D4 and D12 (small, well-localised) plus D7 at least as a "detected but not scanned" finding, re-run this matrix, then tag. D5/D6/D10 are rule-quality items that can ride the same patch or go to 3.0.1. D8/D9/D11 are 3.0.x backlog.
