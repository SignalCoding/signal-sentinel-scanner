## As implemented (`fix/v3-smoke-defects` @ `f70f44b`)

Build 0 warnings / 0 errors; **1171/1171** tests (+40: `Rules/SmokeFixRegressionTests.cs` ×36, `McpConnectionHttpTests.cs` ×4 using a loopback `HttpListener` fake). Smoke matrix re-run recorded in `2026-09-20_v3.0.0-smoke-test.md` section 5.

Deviations from the table above:

- **D1**: the fallback retry triggers on an `InvalidOperationException` whose message starts with `MCP error:` (the client's JSON-RPC error wrapper), not on any error. The negotiated version is sanitised (≤10 chars, digits and dashes) before it is placed in the `MCP-Protocol-Version` header. `BuildInitializeParams(string)` is `internal static` for tests.
- **D3**: request construction factored into `CreateHttpPost(json)` (URL validation, `Mcp-Session-Id`, `MCP-Protocol-Version`) and `CaptureSessionId(response)`; both `SendHttpRequestAsync` and `SendNotificationAsync` use them.
- **D7**: triggers on 405 or 404 only (400 dropped: several Streamable HTTP servers answer 400 to a malformed session and that is not evidence of legacy SSE). GET probe uses a 5 s timeout and `ResponseHeadersRead`. `LegacySseEndpointException(int postStatusCode)` (no URL parameter, CA1054). `LegacySseEvidence { PostStatusCode }` record on `ServerEnumeration`; `ConnectionError` text "Legacy HTTP+SSE transport detected - not scanned".
- **D5**: implemented as a `\b` after the verb alternative in INJECTION-001 (`InjectionPatterns.cs:103`), so "never return**s**" / "never reveal**s**" fall outside the match while imperative "NEVER return" still matches. Simpler than an explicit negation list and covers all third-person forms.
- **D6**: `ClassifyCredentialAccess(name, description)`: name match (separators normalised to spaces) → Critical; any sentence containing a negated credential noun (negation within 4 words before or after) → no finding; disclosure verb ≤5 words before or ≤3 words after the noun → Critical (confidence 0.9, evidence = sentence); consumption context ("API key is optional", "requires a token") → skip; otherwise High (0.7). Bare `token` was not special-cased separately; the negation/consumption logic covered the Chainflip cases. PII: `PersonKeywords` now `customer|patient|employee|member|profile|identity|user\s+(data|records?|…)`, and a person word and a store word must share a sentence. `query` and `read` removed from the database/file sets.
- **D10**: single `CredentialMaterial` regex (credentials, secrets, passwords, api keys, private keys, access/bearer/refresh/session tokens, ssh keys) over name + URI + description → High "Resource Advertises Credential Material"; `SensitivityLabel` (confidential, classified, restricted, internal-only, do not share) → Medium "Resource Marked Confidential or Restricted". Existing Critical name-based `SensitiveFileUri` finding unchanged, so ch6 `get_api_keys` now carries both.
- **Fixtures**: Learn, Hugging Face, Chainflip, DeepWiki captured. DVMCP tool lists were not captured as fixtures (stdio-only, container-dependent); the DVMCP expectations are covered by the live re-run and by inline test cases built from the challenge descriptions. Tests assert "no SS-008 Critical and no SS-001" on the clean fixtures rather than grade ≥ B (grade depends on SS-003 no-auth, which is genuine for public servers).
- **D6 observation**: DVMCP ch2 `search_company_database` is now SS-008 **High** (the spec expected Critical). The description places "must include" and "secret" in different clauses beyond the disclosure window; SS-001 High still fires on the same sentence.
